১. ভূমিকা ও মূল আর্কিটেকচার ওভারভিউ (ARCHITECTURE OVERVIEW)
-------------------------------------------------------------------------------

TopMCQBD প্রজেক্টের ফ্রন্টএন্ড এবং এজ (Edge) লেয়ারটি ক্লাউডফ্লেয়ারের অত্যাধুনিক 
সার্ভারলেস প্রযুক্তির ওপর ভিত্তি করে নির্মিত। ঐতিহ্যবাহী একক সার্ভার আর্কিটেকচারের 
পরিবর্তে এখানে গ্লোবাল এজ নেটওয়ার্ক (Edge V8 Isolates) ব্যবহার করা হয়েছে, যা 
যেকোনো স্থান থেকে ০–১৫ মিলিসেকেন্ডের মধ্যে ইউজারদের দ্রুততম রেসপন্স প্রদান করে।

প্রজেক্টে ক্লাউডফ্লেয়ারের দুটি প্রধান ব্যাকএন্ড প্রযুক্তি ব্যবহৃত হয়েছে:

  ১. Cloudflare Pages API (Pages Functions - Account 1):
     - ফোল্ডার লোকেশন: `functions/api/`
     - লাইভ প্রোডাকশন ডোমেন: `https://topmcqbd.pages.dev`
     - সংশ্লিষ্ট ক্লাউডফ্লেয়ার একাউন্ট: `mosabber480` (Gmail Account 1)
     - ডিপ্লয় কমান্ড: `npm run pages:deploy`
     - রানটাইম: Cloudflare V8 Workers Isolate (`nodejs_compat` ফ্ল্যাগ সক্রিয়)
     - মূল দায়িত্ব: 
       • Cloudflare D1 Serverless SQL ডেটাবেজের সাথে যোগাযোগ (হেডার, ফুটার, মেনু, পলিসি, কনফিগ)।
       • ৬টি MongoDB Atlas ক্লাস্টারের সাথে সরাসরি এজ কানেকশন ও ডেটা লেনদেন।
       • Google Gemini AI টিউটর ইঞ্জিন (`/api/ask-ai`) পরিচালনা।
       • ৩০,০০০+ ইউজারের জন্য গ্লোবাল এজ ক্যাশিং (0ms Latency) নিশ্চিত করা।

  ২. Cloudflare Workers API (Standalone & Backup Gateway - Account 2):
     - সোর্স কোড লোকেশন: `workers/topmcqbd-worker/src/index.js`
     - কনফিগারেশন ফাইল: `workers/topmcqbd-worker/wrangler.jsonc`
     - বিল্ড আউটপুট: `out/_worker.js` (Cloudflare Pages Advanced Mode)
     - ব্যাকআপ ওয়ার্কার লাইভ ডোমেন: `https://topmcqbd-backup-api.mosabber5266.workers.dev`
     - সংশ্লিষ্ট ক্লাউডফ্লেয়ার একাউন্ট: `mosabber5266` (Gmail Account 2 — সম্পূর্ণ পৃথক ক্লাউডফ্লেয়ার একাউন্ট)
     - ডিপ্লয় কমান্ড: `npm run worker:deploy`
     - মূল দায়িত্ব:
       • `npm run build` চলাকালে `build-pages.js` স্ক্রিপ্টের মাধ্যমে পূর্ণাঙ্গ সাইটকে এজ ওয়ার্কারে রূপান্তর।
       • স্ট্যাটিক অ্যাসেটস সার্ভ করা ও ক্লিন ইউআরএল রাউটিং হ্যান্ডেল করা (যেমন: `/questions` -> `questions.html`)।
       • কোনো থার্ড-পার্টি ক্লাউড সার্ভার বা Render ডিপেনডেন্সি ছাড়া সার্বক্ষণিক ব্যাকআপ এজ ব্যাকএন্ড প্রদান।

২. সিকিউরিটি আর্কিটেকচার ও ডেটাবেজ কি (KEY) নিরাপত্তা

-------------------------------------------------------------------------------
[ক] জিরো ক্লায়েন্ট এক্সপোজার (Zero Client-Side Exposure):
-------------------------------------------------------------------------------
১. ব্রাউজার বা সাধারণ ইউজার কখনোই ডেটাবেজ ক্রেডেনশিয়াল দেখতে পায় না।
২. কোনো ডাটাবেজ ভেরিয়েবলের সাথে `NEXT_PUBLIC_` প্রিফিক্স নেই; ফলে Next.js ক্লায়েন্ট 
   বান্ডেল বা ব্রাউজারের "Inspect Element / Network Tab"-এ ডাটাবেজ ইউআরএল বা কি উন্মুক্ত হয় না।
৩. ব্রাউজার শুধুমাত্র পাবলিক এন্ডপয়েন্টে (যেমন: `/api/layout-config` বা `/api/db-test/paid`) 
   রিকোয়েস্ট পাঠায়। এজ সার্ভার ইন্টারনালি ডেটা প্রসেস করে কেবল সুরক্ষিত JSON ডাটা রিটার্ন করে।

-------------------------------------------------------------------------------
[খ] জিরো হার্ডকোডিং ও ক্লাউড সিক্রেটস:
-------------------------------------------------------------------------------
১. সোর্স কোডের (`src/`, `functions/`, `workers/`) কোনো ফাইলে কোনো ইউজারনেম, পাসওয়ার্ড 
   বা ডাটাবেজ লিঙ্ক সরাসরি লিখে রাখা হয়নি।
২. সমস্ত সংযোগ রানটাইমে ক্লাউডফ্লেয়ার ড্যাশবোর্ড সিক্রেট (`env.MONGODB_URI_*`) 
   এবং লোকাল মেশিনে `.env` ফাইল থেকে লোড হয়।
৩. সকল ডাটাবেজ কানেকশনে `tls: true` এবং SSL এনক্রিপশন বাধ্যতামূলক, ফলে ডাটা ট্রানজিটের 
   সময় সর্বোচ্চ নিরাপত্তা বজায় থাকে।

[খ] এজ লেভেলে MongoDB Atlas কানেকশন (functions/api/db-test/[cluster].js):
-------------------------------------------------------------------------------
Cloudflare Pages Function থেকে কোনো বাহ্যিক সার্ভার ছাড়া সরাসরি MongoDB-তে 
যুক্ত হওয়ার জন্য অপ্টিমাইজড আর্কিটেকচার:

১. `nodejs_compat` মোড:
   `wrangler.json` ফাইলে `"compatibility_flags": ["nodejs_compat"]` থাকায় 
   ক্লাউডফ্লেয়ার এজে অফিসিয়াল `mongodb` নোড ড্রাইভার (`MongoClient`) সরাসরি কাজ করে।

২. অপ্টিমাইজড ক্লায়েন্ট অপশনস:
   ```javascript
   const clientOptions = {
     tls: true,               // বাধ্যতামূলক TLS/SSL এনক্রিপশন
     family: 4,               // IPv6 DNS ল্যাটেন্সি এড়াতে IPv4
     maxPoolSize: 1,          // প্রতিটি এজ আইসোলেটের জন্য মাত্র ১টি হালকা সকেট
     minPoolSize: 0,          // আইসোলেট নিষ্ক্রিয় হলে সকেট স্বয়ংক্রিয়ভাবে বন্ধ
     connectTimeoutMS: 8000,
     serverSelectionTimeoutMS: 8000,
     socketTimeoutMS: 12000,
   };
   ```

৩. ক্লাস্টার রাউটিং:
   • `paid`          -> `TopMCQBD_DB` (User, Auth, Payments)
   • `free`          -> `TopMCQBD_DB_Free` (Open Free MCQs)
   • `subjective`    -> `TopMCQBD_DB_Subjective` (Subjective MCQs)
   • `live_exam`     -> `TopMCQBD_DB_Live_Exam` (Live Model Test)
   • `written`       -> `TopMCQBD_DB_written` (Written Exam)
   • `question_bank` -> `TopMCQBD_DB_Question_Bank` (Question Bank)

৪. CRUD মেথড সাপোর্ট:
   • `onRequestGet`: কালেকশনের পিং স্ট্যাটাস, ল্যাটেন্সি, কালেকশন লিস্ট ও রেকর্ড লিস্ট প্রদান করে।
   • `onRequestPost`: নতুন রেকর্ড `insertOne` বা মাল্টিপল রেকর্ড `insertMany` করে।
   • `onRequestPut`: নির্দিষ্ট আইডি এডিট করা অথবা ড্র্যাগ-অ্যান্ড-ড্রপ রি-অর্ডারিং আপডেট করে।
   • `onRequestDelete`: নির্দিষ্ট আইডির রেকর্ড ডাটাবেজ থেকে মুছে ফেলে।
   • `onRequestOptions`: ব্রাউজারের প্রি-ফ্লাইট CORS রিকোয়েস্টে 200 OK রেসপন্স দেয়।

-------------------------------------------------------------------------------
[গ] Cloudflare D1 Serverless SQL ডেটাবেজ ম্যানেজমেন্ট:
-------------------------------------------------------------------------------
Cloudflare D1 হলো এজ-নেটিভ সার্ভারলেস SQL ডেটাবেজ (SQLite ভিত্তিক)।
- বাইন্ডিং ভেরিয়েবল: `env.DB` (`wrangler.json` ও Cloudflare ড্যাশবোর্ডে কনফিগার করা)
- ডেটাবেজ নাম: `topmcqbd-db` (ID: `6717c9b8-4836-438d-a042-f2a8a65124c6`)
- টেবিল নাম: `app_configs`
- স্কিমা: `key TEXT PRIMARY KEY, data TEXT, updated_at TEXT`
- মেকানিজম:
  সাইটের হেডার, ফুটার, মেনু বা স্লাইডার কনফিগ D1-এর `app_configs` টেবিলে সংরক্ষিত থাকে। 
  ভিজিটরদের জন্য এজ সিডিএন (Edge CDN) থেকে 0ms-এ ক্যাশড রেসপন্স দেওয়া হয়, যার ফলে 
  D1-এর দৈনিক কোটা সুরক্ষিত থাকে এবং হাজার হাজার পরীক্ষার্থী প্রবেশ করলেও সাইট সুপারফাস্ট থাকে।

[ক] Pages Advanced Mode Worker (`out/_worker.js`):
-------------------------------------------------------------------------------
১. যখন `npm run build` চালানো হয়, তখন `build-pages.js` স্ক্রিপ্টটি 
   `workers/topmcqbd-worker/src/index.js` ফাইলটিকে কম্পাইল করে `out/_worker.js` ফাইলে রূপান্তর করে।
২. Cloudflare Pages ডিপ্লয়মেন্টের সময় এই `_worker.js` সম্পূর্ণ ওয়েবসাইটকে সার্ভ করে 
   এবং ফ্রন্টএন্ড ও ব্যাকএন্ড একসাথে সিঙ্ক রাখে।

-------------------------------------------------------------------------------
[খ] Standalone Worker Backup API:
-------------------------------------------------------------------------------
১. এটি একটি সম্পূর্ণ স্বাধীন ক্লাউড ওয়ার্কার ব্যাকআপ যা ক্লাউডফ্লেয়ার ব্যাকবোন নেটওয়ার্ক ব্যবহার করে 
   মঙ্গোডিবি ও D1 ডেটাবেজের সাথে যোগাযোগ পরিচালনা করতে সক্ষম।
২. Pages Functions ছাড়াও এটি সার্বক্ষণিক সক্রিয় বিকল্প ব্যাকএন্ড হিসেবে কাজ করে।

-------------------------------------------------------------------------------
[গ] সংযোগ স্ট্রিং নির্দেশিকা (MANDATORY `mongodb+srv://` FORMAT):
-------------------------------------------------------------------------------
TopMCQBD প্রজেক্টের Cloudflare Pages API এবং Cloudflare Workers API উভয় পরিবেশেই 
কঠোরভাবে স্ট্যান্ডার্ড **`mongodb+srv://`** প্রোটোকল ব্যবহৃত হচ্ছে:

```env
MONGODB_URI_PAID="mongodb+srv://<DB_USER>:<DB_PASSWORD>@<CLUSTER_NAME>.mongodb.net/<DB_NAME>?retryWrites=true&w=majority"
```

* কঠোর নির্দেশিকা (Strict Architecture Rule):
  ১. কোনো অবস্থাতেই ডিরেক্ট রেপ্লিকা সেট শার্ড স্ট্রিং (`mongodb://...shard-00-00...`) ব্যবহার করা যাবে না।
  ২. ক্লাউডফ্লেয়ার পেজেস ও ক্লাউডফ্লেয়ার ওয়ার্কার উভয়েই সরাসরি স্ট্যান্ডার্ড `mongodb+srv://` 
     ফরম্যাটের সাথে কনফিগার করা এবং এই ফরম্যাটেই সমস্ত ডেটাবেজ অপারেশন পরিচালিত হয়।
  ৩. কোনো ক্রেডেনশিয়াল সোর্স কোডে থাকবে না; এগুলো শুধুমাত্র ক্লাউডফ্লেয়ার ড্যাশবোর্ড সিক্রেট 
     এবং লোকাল `.env` ফাইলে সুরক্ষিত থাকবে।

৫. ডায়াগনস্টিক টেস্ট পেজ আর্কিটেকচার (/db-connection-api)
===============================================================================

প্রজেক্টের ইন্টারনাল সিস্টেম ভেরিফিকেশনের জন্য শক্তিশালী `/db-connection-api` স্যুট 
বিদ্যমান। এর প্রতিটি পেজ আলাদা ক্লাউড সার্ভিসকে পরীক্ষা করার জন্য নিবেদিত:

-------------------------------------------------------------------------------
[১] পেজের স্ট্রাকচার ও কোর স্টেট ম্যানেজমেন্ট:
-------------------------------------------------------------------------------
`/db-connection-api/db-pages-api` এবং `/db-connection-api/db-workers-api` 
উভয় পেজই Next.js Client Component (`'use client'`) হিসেবে তৈরি।
পেজের স্টেট আর্কিটেকচার:
- `clusterData`: ৬টি ক্লাস্টারের ডেটা অবজেক্ট (আইটেম লিস্ট, কালেকশন নাম, ল্যাটেন্সি, কানেক্টেড স্ট্যাটাস)।
- `clusterLoading`: কোন ক্লাস্টারটি বর্তমানে লোড হচ্ছে তার রিয়েলটাইম ট্র্যাকার।
- `isAddingData` ও `newDataRows`: প্রতিটি ক্লাস্টারে আলাদাভাবে মাল্টি-রো ডেটা এন্ট্রি করার ডায়নামিক ইনপুট স্টেট।
- `dragState`, `pendingReorder`: মাউস দিয়ে ড্র্যাগ করে কার্ড উপর-নিচে নিয়ে ক্রম সাজানোর স্টেট।
- `pendingDelete`: ভুলবশত ডিলিট ঠেকাতে ক্লাউড কনফার্মেশন বার স্টেট।
- `refreshFeedback`: প্রতিটি ক্লাস্টারের জন্য আলাদা সবুজ/লাল/নীল নোটিফিকেশন ফিডব্যাক।

-------------------------------------------------------------------------------
[২] CRUD অপারেশন ওয়ার্কফ্লো:
-------------------------------------------------------------------------------

১. কানেকশন চেক ও ডেটা ফেচ (GET Operation):
   - পেজ লোড হওয়ার সাথে সাথে বা "রিফ্রেশ" বাটনে ক্লিক করলে ফাংশনটি কল করে:
     `fetch(`${apiBaseDomain}/api/db-test/${clusterId}`)`
   - এজ ফাংশন থেকে রেসপন্স আসার সময় স্টপওয়াচ কাউন্টারের মাধ্যমে সুনির্দিষ্ট ল্যাটেন্সি (যেমন: `28ms`) হিসাব করা হয়।
   - কানেকশন সফল হলে গ্রিন ব্যাজ (`connected: true`) এবং ব্যর্থ হলে রেড এরর ব্যানার প্রদর্শিত হয়।

২. মাল্টি-রো ডেটা ইনসার্ট (POST Operation):
   - ইউজার "+ নতুন ডাটা যোগ করুন" বাটনে চাপলে একটি ডায়নামিক টেবিল ওপেন হয়।
   - ইউজার একের অধিক সারি (Rows) যোগ করে এক ক্লিকে সেভ করতে পারেন।
   - পেলোড: `POST { text: "নমুনা প্রশ্ন বা টেস্ট টেক্সট" }`
   - এজ ফাংশন মঙ্গোডিবিতে নতুন `_id` জেনারেট করে ডেটা সেভ করে এবং অপটিমিস্টিক্যালি কার্ড যোগ করে।

৩. ইনলাইন এডিটিং (PUT Operation):
   - যেকোনো কার্ডের পেনসিল আইকনে ক্লিক করলে টেক্সটবক্স উন্মুক্ত হয়।
   - সেভ বাটনে চাপলে কল হয়: `PUT { id: "65b...", text: "সংশোধিত টেক্সট" }`
   - ডেটাবেজে `updateOne` এক্সিকিউট হয়ে ফ্রন্টএন্ডে রিয়েলটাইম আপডেট হয়।

৪. ড্র্যাগ-অ্যান্ড-ড্রপ রি-অর্ডারিং (Drag-and-Drop Batch Reorder):
   - ব্যবহারকারী কোনো কোডিং ছাড়া মাউস দিয়ে টেনে আইটেমগুলোর ক্রম (Order) পরিবর্তন করতে পারেন।
   - ড্র্যাগ শেষ হলে নিচে একটি ফ্লোটিং অ্যাকশন বার (Floating Action Bar) ভেসে ওঠে:
     `"ক্রম পরিবর্তন হয়েছে — [বাতিল করুন] [পরিবর্তন সেভ করুন]"`
   - "পরিবর্তন সেভ করুন" চাপলে একসাথে সম্পূর্ণ নতুন অর্ডার মঙ্গোডিবিতে ব্যাচ আপডেট হয়ে যায়।

৫. কনফার্মেশন সহ ডিলিট (DELETE Operation):
   - ট্র্যাশ আইকনে চাপলে সাথে সাথে ডিলিট না হয়ে একটি কনফার্মেশন ফ্ল্যাশ বার আসে।
   - চূড়ান্ত নিশ্চিত করলে কল হয়: `DELETE ${apiBaseDomain}/api/db-test/${clusterId}?id=${item.id}`
   - ডেটাবেজ থেকে `deleteOne({ _id: new ObjectId(id) })` এক্সিকিউট হয়।
